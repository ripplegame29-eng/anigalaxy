# Источники 1080p+: исследование и план

Дата исследования: 03.10.2026. Кода в этом документе нет — только факты, варианты и план.

## 1. Отправная точка (что уже есть в проекте)

- **Kodik — единственный видеоисточник**, его логику менять нельзя:
  `src/lib/kodik.ts`, роуты `/api/kodik/{list,search,title,translations}`, плеер — iframe
  в `src/components/WatchBox.tsx`.
- **`src/lib/shikimori.ts`** уже подключает открытые метаданные по `shikimori_id`
  (постеры, скриншоты, трейлеры, рейтинги), есть свой `memo`-кэш.
- Вывод: точка расширения — новый слой `src/lib/sources/*` + отдельные роуты
  `/api/<source>/*` + ветка выбора источника в `WatchBox`. Kodik не трогается.

## 2. Проверенные факты (с замерами)

| Факт | Значение | Как проверено |
| --- | --- | --- |
| YouTube RSS без ключа | `feeds/videos.xml?channel_id=…`, **ровно 15 последних записей** | Запрос к каналу Muse Asia: HTTP 200, 37 КБ, 15 `<entry>`, заголовки `A Certain Magical Index - Episode 02 [English Sub]`, `Fairy Tail - Episode 018 (S1E18) [English Dub]` |
| Заголовки серий форматируемы | регулярка `«Название» - Episode NN (+Season/сезон) (+Sub/Dub)` | те же 15 записей |
| YouTube Data API v3 | бесплатно, **10 000 юнитов/день** на проект; `search.list` = 100, `playlistItems.list` = 1, `channels.list` = 1 | официальный калькулятор квоты Google (2026) |
| Стоимость полного синка | канал ≈ 1 `channels.list` + N `playlists.list` (по 1) + 1 юнит на каждые 50 серий → **две ленты укладываются в 1–2 тыс. юнитов**, дельта в день ≈ 50–100 | расчёт по калькулятору |
| AniList GraphQL | без ключа, **90 запросов/мин** (бывают деградации до 30) | docs.anilist.co/guide/rate-limiting |
| Jikan (MyAnimeList) | без ключа, 60/мин, 3/сек, ~2000/IP/день | docs.api.jikan.moe |
| Internet Archive | `advancedsearch` с фильтром по полю `licenseurl`, есть официальный iframe-embed | help.archive.org |
| Гео-ограничения | Muse Asia / Ani-One Asia легально вещают **только в отдельных азиатских регионах** → embed может вернуть ошибку плеера | официальное описание каналов |

## 3. Варианты

### A. Официальные YouTube-каналы (рекомендуется для «1080p и выше»)
Полные серии с рекламой, бесплатно и легально: **Muse Asia** (`UCGbshtvS9t-8CW11W7TooQg`),
**Ani-One Asia**, **Crunchyroll** (часть каталога), **Ani-One India**, **RetroCrush**,
региональные «anitime»-каналы студий.

- Качество: встроенный плеер отдаёт до **1080p**, `playerVars.hd = 1` включает HD по умолчанию;
  4K встречается редко.
- Получение списка серий: ключ Data API → `channels.list` (uploads-плейлист) →
  `playlists.list` (по одному плейлисту на тайтл) → `playlistItems.list` (серии по порядку).
  Без ключа доступен только RSS на 15 последних видео — достаточно для «свежих серий»,
  но не для всего каталога.
- Встраивание: официальный YouTube IFrame API (это и есть штатный способ встраивания,
  ничего парсить в обход не нужно).
- Минусы: нужен бесплатный ключ Google Cloud; гео-блоки (надёжный фолбэк на Kodik);
  плейлист может быть от автора скрыт/удалён.

### B. Метаданные из открытых API (без видео)
AniList GraphQL (90/мин, без ключа), Shikimori (уже используем), Jikan/MAL (60/мин).
Даёт: синопсисы, жанры, рейтинги и голоса, даты выхода серий (airing schedule),
хронологию франшиз, персонажей, альтернативные названия для сопоставления.
Не даёт: само видео. Зато полностью легально и почти бесплатно технически.

### C. Internet Archive с открытыми лицензиями
Фильтр по `licenseurl` (Creative Commons / public domain), прямые MP4, официальный embed.
Качество 1080p+ встречается. Минус: свежих лицензионных тайтлов почти нет — в основном
старое/свободное аниме и фанатские работы (которые как раз надо исключать фильтром).

### D. Разбор пиратских риперов и HLS-агрегаторов — **не делаем**
Два независимых основания: (1) перераспространение чужого контента — это то, что я не
реализую; (2) чисто инженерно это худший вариант: подписанные ссылки с TTL в минуты,
HLS + AES-ключи на отдельных доменах, Cloudflare-челленджи, обфускация плеера, вёрстка
меняется каждые пару недель. Парсер будет ломаться еженедельно, а выхлоп — постоянные
претензии и нестабильный плеер.

## 4. Рекомендация: три этапа

### Этап 1 — метаданный слой (1–2 дня)
- Новый `src/lib/anilist.ts`: поиск по названию, рейтинги, жанры, синопсис, airing schedule.
- Обогащение карточек и страницы тайтла там, где Kodik/Shikimori не дают данных.
- Источник данных — открытый GraphQL, ключ не нужен, кэш через существующий `memo`.

### Этап 2 — YouTube как «второй источник» на странице тайтла (3–5 дней)
- `src/lib/sources/youtube.ts`: `channels.list` → `playlists.list` → `playlistItems.list`,
  серверный кэш (тот же паттерн, что `memo` в `kodik.ts`), ключ `YOUTUBE_API_KEY`
  только в `.env.local` (по аналогии с `KODIK_TOKEN`).
- `/api/youtube/title?id=…` — список серий тайтла (номер серии парсим из заголовка).
- `WatchBox`: ветка «Источник: Kodik | YouTube 1080p» — при выборе YouTube рендерим
  iframe IFrame API с `hd=1`, озвучка = оригинальная дорожка + субтитры канала.
- Обработка ошибок: `onError` (коды 101/150/200 — «нельзя встраивать/регион») →
  автоматически возвращаемся на Kodik и показываем честную подпись, почему.
- Сопоставление YouTube-плейлиста с нашим тайтлом — см. §5.

### Этап 3 — вкладка «Смотреть легально» в каталоге (2–3 дня)
- Отдельная секция/фильтр с тайтлами, у которых есть легальный YouTube-плейлист.
- Повторяет устройство существующих лент главной (`AnimeRow`), не ломает Kodik-каталог.

## 5. Схема сопоставления названий (алгоритм, без кода)

1. Нормализация строки: lowercase, убрать пунктуацию, кавычки, «The», маркеры сезона,
   `[English Sub]` / `[English Dub]` / `(S1E02)`.
2. Сравнение с тремя полями из Shikimori/AniList: romaji, english, synonyms
   (у Kodik уже есть `shikimori_id` — связка не нужна, берём названия по нему).
3. Номер серии — регуляркой из заголовка (`Episode 018`, `E18`, `第18話`).
4. Порог уверенности ≥ 0.9 → связываем автоматически; ниже → ручная карта
   `src/lib/sources/youtube-map.ts` (точно так же, как мы вручную закрепляли Kodik-ID).
5. Результат синка кэшируется на сервере (срок суток), чтобы не жечь квоту.

## 6. Правовой контур (соблюдаем)

- Только официальный встроенный плеер — потоки не перехватываем и не пере-хостим.
- Гео-блок не обходим: если плеер недоступен в регионе — просто показываем Kodik.
- Данные берём из API, а не скрейпим HTML (скрейпинг YouTube запрещён его ToS).
- Рядом с плеером — атрибуция правообладателя и ссылка на оригинальное видео.

## 7. Что нужно решить перед стартом

1. **Ключ YouTube Data API** (Google Cloud project → включить YouTube Data API v3 →
   скопировать ключ в `.env.local`). Бесплатно, настройка ~10 минут. Без ключа этапы 2–3
   возможны только в урезанном виде (RSS на 15 последних видео).
2. Какой набор каналов: только азиатские (Muse Asia, Ani-One), или + Crunchyroll/RetroCrush.
3. Режим показа: отдельная опция «1080p на YouTube» на странице тайтла или полноценная
   вкладка каталога.
4. Охват: весь архив каналов или только текущий сезон (квота и так позволяет оба,
   но сопоставлять меньше — дешевле и чище).
5. Согласование: оставляем Kodik основным источником (как договаривались), YouTube —
   как видимую альтернативу.

## 8. Открытые вопросы

- Сколько серий реально доступно в каждом канале без региональных ограничений —
  первым же запросом после получения ключа замеряем (`channels.list` + `playlists.list`).
- Будут ли у каналов субтитры на русском (пока видны только `[English Sub]`/`[English Dub]`) —
  влияет на то, как показывать плеер русскоязычной аудитории.
- Насколько стабильны playlist-id со временем (переименования/архивы плейлистов) —
  нужен периодический пересинк с мягкой инвалидацией кэша.
