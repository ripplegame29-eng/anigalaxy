# AniGalaxy — каталог и просмотр аниме

Современный сайт просмотра аниме на **Next.js 16 (App Router) + TypeScript + Tailwind CSS 4**.
Весь видеоконтент (плеер, серии, озвучки) приходит из **Kodik API**, токен хранится только на
сервере — в браузер он не попадает, CORS не возникает.

## Возможности

- **Главная** — hero-слайдер из **5 закреплённых тайтлов**: фон каждого слайда — локальный
  **ролик** из `public/video` (зациклен, без звука и без органов управления), под ним —
  постер с Ken-Burns как подложка на время загрузки; автопрокрутка с паузой при наведении,
  плашки (статус, рейтинг), метаданные (год, формат, серии), описание, кнопки
  «Смотреть»/«Подробнее»; переключение слайдов — только прогресс-точки по центру снизу;
  под ним — ряды «Онгоинги»,
  «Новинки сезона», «Топ рейтинга», «Аниме-фильмы», быстрый переход по жанрам.
  Карточки в рядах — крупные, фиксированной ширины (160 px на мобильных, 184 px на
  планшете, 200/216/224 px на десктопе — ~5 в ряд), как на референсе animeon.cc;
  прежние процентные ширины давали на десктопе 154–192 px.
- **Шапка** — полупрозрачная с `backdrop-blur`; кнопка **PREMIUM** (неоновая обводка, свечение)
  ведёт на страницу `/premium`, кнопка **Войти** (градиентная с глоу) открывает модалку
  авторизации; живой поиск, адаптивное меню.
- **Аккаунт** — модалка входа/регистрации (переключатель «Вход / Регистрация», показ пароля,
  валидация с русскими подсказками, декоративная левая панель), во вкладке «Вход» — кнопка
  **«Продолжить через Telegram»** (демо-режим без бота: выбор из трёх аккаунтов, аккаунт
  создаётся локально — честно подписано бейджем «демо»). Данные лежат только в
  `localStorage` браузера — сервера у проекта нет. После входа кнопка «Войти» превращается
  в аватар с меню: «Мой профиль», «Каталог», «Premium», «Выйти».
- **Данные и бэкапы** — вкладка «Данные» в настройках профиля: статистика хранилища
  («Ключей: N · объём»), «Экспорт бэкапа (.json)» собирает все ключи `animehub:*` в один
  файл, «Импорт из файла» валидирует его до записи и восстанавливает данные (снимок
  перед импортом даёт кнопку «Откатить последний импорт»).
- **Premium** (`/premium`) — копия референсной страницы: герой «Раскрой полный потенциал»,
  три тарифа (149 ₽ / 349 ₽ / 1290 ₽ со старыми ценами, скидками и «ХИТ ПРОДАЖ»),
  список привилегий, блок промокода (локальная проверка), FAQ. Кнопка тарифа работает в
  трёх состояниях: не вошли → модалка входа, вошли → активация подписки, подписка есть →
  дата окончания.
- **Профиль** (`/profile`) — карточка аккаунта, статус и дата Premium, счётчики избранного и
  подборок, выход; без входа показывает приглашение авторизоваться (страница закрыта от
  индексации).
- **Каталог** — фильтры по типу, статусу, жанру, формату и диапазону лет, 6 сортировок,
  живой поиск по названию, кнопка «Показать ещё» с курсорной пагинацией.
- **Страница тайтла** — крупный постер-акцент (колонка 280→330px, оверлей и кнопка «Смотреть»
  при наведении), рейтинг (Shikimori → Кинопоиск → IMDb), метаданные, жанры,
  описание, JSON-LD, похожие тайтлы; под ними — **комментарии** (счётчик,
  сортировка новые/старые/популярные, композер со спойлером и Ctrl+Enter,
  карточки с бейджом уровня и тегом автора, ответы, лайки, «⋮ → Удалить»;
  локальные, с честным демо-посевом первого визита). Тот же блок — раздел
  «Комментарии» в профиле (стена).
- **Избранное и подборки** — кнопки «В избранное» и «В подборку» рядом со «Смотреть онлайн».
  Модальное окно позволяет отметить тайтл в существующих подборках или создать новую
  (поле ввода + «Создать» — тайтл попадает в неё сразу). Всё хранится в `localStorage`,
  сервер ничего не знает об этих списках.
- **Хронология франшизы** — горизонтальная лента всех частей (сезоны, спешлы, OVA, фильмы)
  в порядке выхода, с постером, годом, типом и подсветкой текущего тайтла;
  лента прокручивается к активной части при загрузке, по бокам — круглые
  стрелки прокрутки (они всегда на месте, но гаснут, когда листать некуда).
  Если частей мало и ряд не заполняет ширину — карточки центрируются
  (`mx-auto` у гибкого списка), при переполнении авто-поля обнуляются
  и лента листается от края. Дубли одной части (анонс и вышедшая запись
  с разными годами) склеиваются в одну.
- **Кадры из аниме** — по умолчанию показано 4 кадра (включая трейлер),
  под ними кнопка «Показать все кадры» раскрывает всю галерею с Shikimori.
  Клик открывает полноэкранный лайтбокс (←/→ листают, Esc закрывает,
  счётчик «3 / 12»), первый слот — трейлер с YouTube, который открывается
  тем же просмотрщиком.
- **Просмотр** — iframe Kodik, вписанный в дизайн (склонность кегля, кольца, скелетон загрузки),
  боковая панель со студиями озвучки и выбором серий/сезонов, deep-links `?tr=&s=&ep=`.
  **Полноэкранный режим работает**: у iframe прописан `allow` с явным origin-списком —
  `autoplay *; fullscreen *; picture-in-picture *; encrypted-media *`. Без звёздочек Chrome
  трактует имя как «разрешено только своему origin», cross-site кадру Kodik выдаёт отказ и
  `requestFullscreen()` падает с `TypeError: Disallowed by permissions policy`; то же касалось
  автозапуска и PiP. Проверено e2e через CDP: клик по кнопке плеера → `document.fullscreenElement`
  в родителе и внутри кадра, выход — штатный, в том числе при включённом режиме «Апскейл 2x».
- **Качество изображения** — селектор «Оригинал / HD+ / Апскейл 2x» под плеером (общий
  для сайта, выбор хранится в `localStorage`); после переключения над плеером на пару
  секунд всплывает подпись о применённом режиме. Плеер Kodik — iframe чужого домена,
  страница физически не может читать его пиксели (tainted canvas), а SVG `url(#…)`-фильтры
  браузер к таким кадрам вообще не применяет (проверено замерами 0/255) — поэтому база
  под шейдером и запасной путь сделаны CSS-фильтрами на самом iframe (контраст/цвет),
  а на локальных hero-ролях главной работает WebGL-шейдер (`lib/video-shader.ts`).
  Режим **«Апскейл 2x»** — настоящий GPU-конвейер поверх плеера: `getDisplayMedia`
  (`preferCurrentTab`, одно подтверждение браузера) + `RestrictionTarget.fromElement`
  (Element Capture, Chrome 132+) превращают поток в захват только пикселей iframe,
  кадры идут через `MediaStreamTrackProcessor` → WebGL → непрозрачный канвас поверх
  iframe (клик проходят сквозь: звук, управление и фулскрин остаются у плеера).
  Основной путь шейдера — настоящий **Anime4K** (bloc97, MIT): движок `lib/anime4k.ts`
  исполняет пользовательские шейдеры mpv (Restore-CNN + Upscale-CNN ×2, тексты в
  `lib/anime4k-shaders.ts`), запасной — Catmull-Rom-ресемплинг 2× + нерезкая маска
  с локальным клампом. Отказ в разрешении, браузер без API, потеря контекста WebGL —
  всё аккуратно деградирует до CSS-пути. Какой движок отработал кадр, видно в
  инспекторе: `canvas[data-upscale-engine]` = `anime4k` | `catmull`. Честная подпись
  в списке: источник Kodik — до 1080p, 2x создаётся апскейлом в браузере.
- **Бренд** — логотип **AniGalaxy** нарисован с нуля в SVG (`src/components/LogoMark.tsx`,
  viewBox 66×38): монограмма «A» с градиентной перекладиной, наклонная орбита
  (дальняя половина уходит за букву, ближняя проходит поверх неё) и четырёхлучевая
  искра в левом верхнем углу. Знак вставлен инлайном в шапку, футер и левую панель
  модалки (`<Logo/>`, `h-9 w-[62px]`, свечение — `drop-shadow` по альфа-краю), поэтому
  рамок и «полей» у картинки нет — фона просто не существует. Фавикон — `src/app/icon.svg`
  (тот же знак на тёмной скруглённой подложке `#07070c`) плюс растровый фолбэк
  `src/app/icon.png` 512×512; старые `favicon.ico` и `public/logo-anigalaxy.png` удалены.
  PNG-фолбэк собирается из того же `icon.svg` подстановкой сплошных цветов (сборка libvips
  в проекте не умеет рисовать градиенты `url(#…)`), готовность проверяется по доле синих
  пикселей — 16 %. Палитра акцентов (`globals.css`) сине-голубая: `--color-accent #1f7bff`
  → `--color-accent-2 #00c8ff`, на них построены все градиенты кнопок, свечения и обводки
  (раньше было `#7c5cff → #ff4d9d`).
- Тёмная тема, адаптивность ПК/планшет/мобайл, плавные CSS-анимации, `next/image` для постеров.

## Переменные окружения

`.env.local`:

```bash
KODIK_TOKEN=ваш_токен
KODIK_API_URL=https://kodik-api.com   # домен kodikapi.com не резолвится
SHIKIMORI_API_URL=https://shikimori.io   # опционально; иначе пробуются shikimori.io → shikimori.one
```

Токен используется только в `src/lib/kodik.ts` (серверные Route Handlers и Server Components).

## Как работает Kodik

- Запросы идут **POST** на `https://kodik-api.com/<path>?token=...&<params>`.
- Методы: `/search`, `/list`, `/genres`, `/years`.
- Пагинация курсорная: `next_page` → параметр `next`.
- Озвучки в публичном API нет — они парсятся из `<select>` на странице плеера
  (`data-media-id`, `data-media-type`, `data-episode-count`); каждая озвучка = отдельный
  материал, серии берутся через `search?id=<mediaId>&with_seasons=1&with_episodes=1`.
- Ответы кэшируются в TTL-кэше процесса (POST Next не кэширует).
- **Трейлеров и связей франшизы в API нет**. В `material_data` есть только постеры/рейтинги/
  описания, из видео — лишь кадры `screenshots`; прямых адресов файлов в HTML плеера тоже нет
  (их отдаёт только защищённый бандл по `vInfo.hash`). Поэтому:
  - **хронология** собирается в `franchise()` — база названия без номера сезона
    («Блич [ТВ-1]» → «Блич») подаётся в `/search`, а случайные совпадения отсекаются
    пересечением токенов названий; Kodik сам даёт рабочие ссылки и постеры частей;
  - **кадры и трейлеры** берутся из `src/lib/shikimori.ts` по `shikimori_id` из ответа Kodik.
    Shikimori (`/screenshots` — 29–40 картинок, `/videos` — YouTube-ролики с русскими
    названиями). Рабочий origin выбирается на лету: `shikimori.io` → `shikimori.one`
    (на машине с системным прокси `.one` не резолвится напрямую из Node), при полной
    недоступности страница откатывается на `screenshots` из Kodik, а трейлер ищется поиском
    YouTube. Фон hero-слайдера — **локальные ролики** из
  `public/video`, привязанные вручную в `HERO_SLIDES` (`page.tsx`), т.е. файл всегда
  соответствует своему тайтлу. Ролик играет **без звука и без органов управления**, пока он
  грузится — видно постер/Ken-Burns-подложку; плеер и видео Kodik живут только на странице
  тайтла. Случайных чужих MP4 в проекте нет.

### Особенность: дубли в выдаче

Kodik возвращает **один и тот же тайтл разными material-id** (по записи на каждую озвучку).
При сортировке по рейтингу первая страница может состоять целиком из дублей одного аниме.
Поэтому `src/lib/kodik.ts` добирает страницы (`collectUnique`), а `src/lib/anime.ts`
(`cardKey` / `dedupeCards`) склеивает дубли по «название + год + формат». То же применяется
на клиенте при «Показать ещё» и в поиске шапки.

## Деплой

```bash
npm run build && npm start
```

Vercel/Node.js-хостинг: задайте `KODIK_TOKEN` в настройках проекта. Дополнительных
зависимостей кроме `server-only` нет; анимации — чистый CSS/Tailwind, шрифт Manrope
загружается через `next/font/google`.

Оптимизация под хостинг: модалки (вход/настройки) подгружаются лениво и не входят в
стартовый бандл (≈290 КБ gzip на страницу, полифилы Next уходят под `noModule`),
картинки `loading="lazy"`, рамки аватаров кэшируются на год (`immutable`), постеры —
сутки. Перед загрузкой на новый хостинг данные можно перенести кнопкой
«Экспорт бэкапа» → «Импорт из файла».
